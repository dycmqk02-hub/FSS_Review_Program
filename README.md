# 보고서 Review프로그램

분·반기재무제표 검토보고서(추후 감사보고서로 확장 예정)를 업로드하면, 「분·반기재무제표
검토준칙」 문단46 필수 기재사항, 의견유형, 비교표시 재무정보, 회계처리 변경 키워드, 표
소계·합계 검산, 연결·별도 비교 등을 **규칙/키워드 기반으로 1차 스크리닝**해 주는 데스크톱
프로그램입니다.

> **중요**: 이 프로그램은 LLM(AI) 판단 없이 순수 규칙/키워드 매칭만 수행하는 **1차 스크리닝
> 보조도구**입니다. 실질적 회계 판단(준칙 준수 적절성, 증감분석 적절성, 왜곡표시 중요성
> 평가 등)과 최종 검토의견 형성은 반드시 검토자가 직접 수행해야 합니다. 특히 숫자 합계
> 검산·라벨 교차대사·회계처리 변경 탐지는 PDF 텍스트/표 추출 기반 휴리스틱이므로 **오탐
> (false positive)과 누락(false negative)이 모두 발생할 수 있습니다.**

## 1. 실행 방법

### 방법 A - 파이썬으로 바로 실행 (권장, 가장 안정적)
```
cd FSS_Review_Program
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

### 방법 B - EXE 빌드 후 실행 (권장 - 파이썬 설치 불필요)
```
build_exe.bat 더블클릭 (또는 cmd에서 실행)
```
빌드가 끝나면 `dist\FSS_ReviewProgram.exe`가 생성됩니다. **탐색기에서 더블클릭하면 바로
실행됩니다.** (자동화 스크립트/에이전트 도구 등 제한된 셸 환경에서 실행을 시도하면 Smart
App Control 등 보안 정책에 막힐 수 있으나, 일반 데스크톱 사용(더블클릭)에는 영향이 없음을
확인했습니다.)

EXE는 파이썬 인터프리터와 모든 라이브러리가 내부에 포함된 완전한 독립 실행파일이므로,
사용자 PC에 파이썬이 설치되어 있지 않아도 동작합니다.

## 2. 화면 구성 (사이드바 옵션)
- **① 보고서 종류**: 분반기 / 감사 (감사는 현재 스텁 - 3번 항목 참고)
- **② 재무제표 구분**: 연결 / 별도 / 개별 / 연결 vs 별도(PDF 2개 업로드)
- **③ 적용 회계처리기준**: KIFRS / 일반기업회계기준
- **④ 연결 PM / ⑤ 별도 PM**: 증감분석표의 "금액차이" 음영 처리 기준값 (5번 항목 참고, 선택 입력)
- **⑥ 보고서 PDF 업로드**: 선택한 옵션에 따라 1개(단일) 또는 2개(연결 vs 별도) 업로드
- **⑦ XBRL 데이터 (선택)**: DART 원문XBRL을 zip 또는 압축 해제한 폴더로 제공하면 증감분석을
  PDF 표 인식 대신 XBRL 원본 수치로 정밀 산출 - 6번 항목 참고
- **⚙ 참조자료 폴더 설정**: K-GAAP·KIFRS 기준서 PDF가 들어있는 로컬 폴더 지정
- **▶ 리뷰 시작 버튼**: 클릭하면 진행률(%)이 버튼 텍스트에 표시되고, 진행률이 오를수록
  버튼 색이 점점 짙어집니다. 완료되면 버튼이 "✓ 리뷰완료"로 바뀌고 가장 짙은 색으로
  고정됩니다(다음 리뷰를 시작하면 다시 0%부터 색이 옅어지며 진행됩니다).

옵션 조합에 따라 8가지(보고서종류 제외) / 16가지(보고서종류 포함, 감사는 스텁) 리뷰
경로가 자동으로 구성됩니다.

## 3. 참조자료 폴더 (K-GAAP / KIFRS 시행중 / KIFRS 조기적용가능)
KIFRS.com·KASB 사이트 모두 로그인 필요 또는 JavaScript 동적 다운로드 방식이라
**자동 스크래핑이 불가능**합니다. 따라서 아래처럼 로컬 폴더 방식을 사용하며, 옵션3에서
KIFRS를 선택하면 "시행중"과 "조기적용가능" 두 폴더를 **동시에** 검색해 결과를 서로 다른
색상 배지로 구분 표시합니다.

기본 설정된 폴더: `C:\Users\seo\1st Review프로그램\기준서`
```
기준서\
 ├─ 분반기재무제표검토준칙.pdf
 ├─ 일반기업회계기준\              ← 옵션3="일반기업회계기준" 선택 시 검색 (민트색 배지)
 │   ├─ 일반기업회계기준1.pdf ... 37.pdf
 ├─ KIFRS\                        ← 옵션3="KIFRS" 선택 시 "시행중" 소스로 검색 (하늘색 배지)
 │   └─ 시행중_K-IFRS_제10xx호_....pdf 등
 └─ KIFRS_조기적용가능\            ← 옵션3="KIFRS" 선택 시 "조기적용가능" 소스로 검색 (피치색 배지)
     └─ 조기적용가능_K-IFRS_제10xx호_....pdf 등
```
하위 폴더까지 재귀적으로 검색하므로, 폴더 구조를 자유롭게 정리해도 무방합니다.
`⚙ 참조자료 폴더 설정`에서 3개 폴더(K-GAAP / KIFRS 시행중 / KIFRS 조기적용가능) 경로를
각각 바꿀 수 있습니다.

**⏱ 첫 실행 시간 안내**: KIFRS 폴더는 PDF가 120개 이상(시행중 63 + 조기적용가능 59)이라
**맨 처음 한 번**은 전체 PDF를 텍스트로 인덱싱하는 데 몇 분 걸립니다(실측 약 9분, 순차 처리
- 스레드 병렬화를 시도했으나 pypdf의 텍스트 추출은 대부분 GIL이 걸리는 순수 파이썬 연산이라
오히려 더 느려져 순차 처리로 되돌렸습니다). 이후에는 **디스크 캐시**(`app\.ref_cache\` 폴더)에
저장되어, **프로그램을 껐다 켜도** 원본 PDF가 바뀌지 않았다면 재파싱 없이 몇 초 만에
불러옵니다(실측 13초). K-GAAP만 사용하는 리뷰는 PDF 수가 적어(38개) 처음부터 빠릅니다.

## 4. 리뷰 결과 탭
- **요약**: 옵션값, 의견유형, 체크리스트 충족률, 합계검산/회계처리변경 건수,
  참조자료 출처별(시행중 KIFRS=하늘색 / 조기적용가능 KIFRS=피치색 / K-GAAP=민트색) 뱃지
- **체크리스트**: 문단46 등 필수 기재사항 체크리스트 + 의견유형 판단 + 비교표시 체크
- **숫자 스크리닝**: 표 소계·합계 검산 불일치 후보 / 동일 라벨 금액 교차대사 후보
- **증감분석**: 재무상태표/손익계산서/자본변동표/현금흐름표의 당기 vs 전기(비교표시)
  증감분석표. 상단에 "산출방식" 배지로 XBRL 정밀매칭(민트)인지 PDF 표 휴리스틱(피치)인지
  표시됩니다 - 자세한 내용은 5·6번 항목 참고
- **합계검증**: 재무제표 계층별 합계검증(leaf→소계→최상위 총계) + FS간 교차검증(동일
  계정과목의 재무제표간 대사) + 주석(Note) 공시 대사. XBRL·PDF 결과가 함께 표시됩니다 -
  자세한 내용은 7번 항목 참고
- **회계처리 변경**: 전기말 대비 당반기중 회계처리 변경 관련 키워드 탐지 결과
- **참조자료**: 탐지된 키워드를 K-GAAP·KIFRS(시행중/조기적용가능) 참조폴더에서 자동 검색한
  매칭 스니펫 - 각 결과 앞에 출처가 색상 배지로 표시되어 어느 기준서에서 나온 매칭인지
  한눈에 구분됩니다.
- **연결 vs 별도**: (해당 모드에서만) 특수관계자/내부거래/투자주식 등 핵심 키워드
  존재 비교 + 실무 참고 체크리스트

결과는 우측 상단 `TXT로 저장` / `DOCX로 저장` / `증감분석 Excel`(색상 음영 포함)로 내보낼 수
있습니다.

## 5. 재무제표 증감분석 (옵션④ 연결PM / 옵션⑤ 별도PM)
재무상태표·손익계산서·자본변동표·현금흐름표 각각에 대해 **당기금액 / 전기금액 / 금액차이 /
증감률(= (당기금액-전기금액) ÷ 전기금액)** 을 계산한 증감분석표를 자동 생성합니다.

**PM(금액차이 기준값) 입력 규칙 - OR 조건**
| 재무제표 구분(옵션②) | 사용되는 PM |
|---|---|
| 연결 | ④ 연결 PM |
| 별도 | ⑤ 별도 PM |
| 개별 | ④ 연결 PM 칸에 입력 (개별 전용 칸은 없음 - ④ 칸을 재사용) |
| 연결 vs 별도 | 연결 문서는 ④, 별도 문서는 ⑤ - 각각 독립적으로 적용(즉 두 값을 함께 입력) |

- ④·⑤ 중 하나라도 값을 입력하면 해당 문서의 금액차이 음영(연노랑)이 활성화됩니다.
  **미입력 시 금액차이 음영은 표시되지 않지만, 증감률 5% 이상 음영(살구색)은 항상 적용**됩니다.
- 두 조건(금액차이 기준 초과 + 증감률 5% 이상)을 모두 만족하는 행은 더 진한 호박색으로
  표시됩니다.
- PM 단위는 재무제표 표시단위(원/천원/백만원 등)와 동일하게 입력해야 합니다. 프로그램이
  본문에서 "단위: OOO" 문구를 감지하면 결과 화면에 참고용으로 표시합니다(자동 환산은
  하지 않습니다).

**추출 방식과 한계 (휴리스틱 - 반드시 육안 확인 필요)**
- 재무상태표/손익계산서/현금흐름표: 표의 각 행에서 인식된 숫자열이 2개면 그대로 당기/전기로,
  4개면(예: 당기 3개월·누적 + 전기 3개월·누적처럼 컬럼이 많은 경우) 앞쪽 절반을 당기,
  뒤쪽 절반을 전기로 보고 위치 기준으로 짝을 지어 "구간1"/"구간2"로 표시합니다. 컬럼의
  실제 의미(3개월인지 누적인지 등)는 자동 판별하지 않으므로 원본 PDF에서 확인하십시오.
- 자본변동표: 당기표와 전기표가 별도의 표로 존재하는 일반적인 레이아웃을 가정하여, 같은
  구간에서 인식된 첫 번째 표(당기)와 두 번째 표(전기)의 행 라벨을 매칭시켜 마지막 숫자열
  (통상 "합계")을 비교합니다. 표가 2개로 인식되지 않으면 "자동 매칭 실패 - 육안 확인
  필요" 안내만 표시됩니다.
- 표 인식 자체가 안 되거나(스캔본 이미지 PDF 등) 숫자열 개수가 특이한 경우(1/3/5개 이상)
  해당 행은 자동 분석에서 제외되고 "표 구조 인식 불가" 안내가 표시됩니다.

## 6. XBRL 기반 정밀 증감분석 (옵션⑦, 선택 기능)
옵션⑦에 DART 원문XBRL(zip 또는 압축 해제한 폴더)을 넣으면, 위 5번의 PDF 표 휴리스틱 대신
**XBRL 인스턴스 문서의 실제 태깅된 수치**를 사용해 증감분석표를 만듭니다. 연결·별도 값이
하나의 XBRL 인스턴스에 모두 들어있으므로 업로드는 1회만 하면 됩니다(재무제표구분 옵션에
따라 연결/별도/개별 중 필요한 쪽을 자동으로 골라 씀 - 개별은 별도 role을 사용).

**leaf(가장 하위계정) 판정 방법** - Presentation/Calculation Linkbase + Abstract 속성을
종합해 "더 이상 쪼갤 수 없고, 다른 항목의 합계도 아닌" 계정만 증감분석 대상으로 삼습니다.
1. Presentation Linkbase의 `presentationArc`(부모→자식, `order`)로 계층 트리 구성
2. 요소명이 `...Abstract`로 끝나면 헤더이므로 제외
3. Calculation Linkbase의 `summation-item` arc에서 합계(from) 역할이면 제외
   (Presentation상 자식이 없어도 "자산총계"처럼 Calculation상 합계면 leaf가 아님)
4. `...Table`/`Axis`/`Domain`/`Member`로 끝나는 차원 메타데이터 요소는 애초에 제외

재무제표 종류(D210000=재무상태표 연결, D210005=별도 등) 역할(role)은 특정 코드로
하드코딩하지 않고, 스키마의 `roleType/definition` 텍스트에서 "재무상태표/손익계산서/
자본변동표/현금흐름표" + "연결/별도" 키워드로 매번 동적 탐색합니다(회사·서식마다 role
코드가 다를 수 있음).

**값 추출**: 인스턴스 문서의 context(기간: instant 또는 duration + 연결·별도 dimension)와
fact를 매칭해 당기/전기 값을 가져옵니다. 재무상태표/손익계산서/현금흐름표는 요소 1개당
연결·별도 축 1개만 확인하면 되지만, **자본변동표는 구조가 달라** 요소(변동유형: 기초자본/
당기순이익/배당 등)마다 "자본구성요소"(자본금/자본잉여금/이익잉여금 등) 축까지 함께
일치해야 값이 나오는 2차원 매트릭스라서 별도 로직(`get_equity_leaf_values`)으로 처리하며,
결과 행은 "변동유형 - 자본구성요소" 형태로 표시됩니다.

실제 상장사 반기보고서 원문XBRL로 검증한 결과, 재무상태표 35/35, 손익계산서 16개 leaf ×
(3개월/누적) 32/32, 현금흐름표 67개 leaf 66~68건, 자본변동표 6개 leaf 중 5개(나머지 1개는
해당 반기에 배당 자체가 없어 값이 존재하지 않는 정상 케이스)로 leaf 계정의 당기/전기 값이
빠짐없이 매칭되었습니다.

XBRL 파싱이 실패하거나(파일 누락, 예상과 다른 구조 등) 아예 제공되지 않으면 자동으로 5번의
PDF 표 휴리스틱으로 폴백하며, 결과 화면 "산출방식" 배지로 어떤 방식이 쓰였는지 항상
확인할 수 있습니다.

## 7. 합계검증 / FS간 교차검증 / 주석 대사 ("합계검증" 탭)
PDF는 항상 수행되고, 옵션⑦에 XBRL을 올리면 정밀 검증이 함께 표시됩니다(둘 다 같은 화면에
"XBRL(정밀 매칭)"/"PDF 표(휴리스틱)" 배지로 구분되어 나옵니다).

**(1) 재무제표 계층별 합계검증** - leaf 계정의 합이 소계와, 소계의 합이 최상위 총계와
맞는지 전 레벨을 검증합니다.
- XBRL: Calculation Linkbase의 부모-자식(weight) 관계를 그대로 사용 - 가장 신뢰도가 높음.
- PDF: 재무제표별로 표 레이아웃을 분석해 별도 규칙을 적용합니다.
  - 재무상태표/현금흐름표: 로마자(Ⅰ/I)·괄호숫자(1)(2) 소계는 세부항목과 다른 컬럼에 값이
    미리 찍혀 있는 경우가 많아 이를 자동 인식하고, "OO총계"류 라벨은 그 앞 로마자 소계들의
    합으로 검증합니다. 현금흐름표는 "(Ⅰ+Ⅱ+Ⅲ+Ⅳ)"처럼 라벨에 수식이 그대로 적힌 경우 이를
    직접 파싱하고, "기말"행은 "기초"행 + 직전 순증감행의 합으로 검증합니다.
  - 손익계산서: 로마자 소계가 "위 항목의 합"이 아니라 직전 소계 ± 다음 항목의 가감 체인이라
    고정 수식(매출총손익=매출액-매출원가, 영업손익=매출총손익-판관비, 세전손익=영업손익+
    기타손익+금융손익, 순손익=세전손익-법인세비용, 총포괄손익=순손익+기타포괄손익 등)으로
    검증하며, "이익(손실)"/"손익"/"지배기업소유지분"/"지배주주지분" 등 회사별 표현 차이는
    키워드 정규화로 흡수합니다.
  - 자본변동표: 가로(소계=구성요소 합, 총계=소계+비지배지분)와 세로(기말=기초+그 사이
    증감행의 합, 컬럼별)를 모두 검증합니다.
  - 주석 표에도 동일 엔진을 적용하되, 실측 검증 결과 로마자/괄호숫자 계층이 없는 "평범한
    항목→합계" 패턴은 표 구조가 워낙 다양해(카테고리별 소계, 다통화 표 등) 오탐이 크게
    늘어남을 확인하여, 주석에서는 로마자/괄호숫자 계층이 명확한 경우만 검증합니다(신뢰도를
    위해 커버리지를 일부 낮춘 의도적 선택).

**(2) FS간 교차검증** - 동일 계정과목이 여러 재무제표에 등장할 때(예: 반기순이익은
손익계산서·현금흐름표·자본변동표에, 자본총계는 재무상태표·자본변동표에 등장) 서로
일치하는지 대사합니다. XBRL은 요소(예: `ProfitLoss`, `Equity`) 재사용 여부로, PDF는 각
표에서 독립적으로 추출한 값끼리 비교합니다. 확인 대상: 반기(당기/분기)순이익, 자본총계,
현금및현금성자산(기말) - PDF만 해당.

**(3) 주석(Note) 공시 대사** - 재무제표 각 계정의 "주석" 컬럼 번호가 가리키는 주석에 그
금액이 실제로 공시되어 있는지 확인합니다.
- XBRL: 재무제표 leaf 요소와 동일한 요소가 주석 role(재무제표 4종 외 모든 role)의
  Presentation Linkbase에도 등장하는지 확인합니다. DART XBRL은 통상 재무제표와 주석이
  같은 context를 재사용하므로 "확인됨"은 주로 태깅 존재(공시 추적) 여부를 의미하며, 주석
  role에 자체 계산관계(Calculation Linkbase)가 정의된 경우 그 계층별 합계도 함께
  검증합니다(재무제표 4종을 제외한 전체 role을 대상으로 함).
- PDF: 재무제표 행의 주석번호가 가리키는 주석 섹션을 자동으로 찾아(제목이 1부터 연속으로
  증가하는 번호 패턴을 스캔 - "재무제표에 대한 주석" 같은 특정 문구에 의존하지 않으므로
  연결/별도 보고서의 서로 다른 주석 제목 표현에도 대응됨) 그 안에 재무제표 금액과 같은
  숫자가 등장하는지 확인합니다. 주석의 "합계행"을 구조적으로 특정하는 대신 "금액이 그
  주석 안에 실제로 등장하는가"를 확인하는 방식이라 표 레이아웃이 달라도 오탐이 적습니다.
  주석이 없거나 서술식으로만 설명된 항목은 "주석 미확인"으로 표시되며, 이는 반드시 누락을
  의미하지 않습니다(육안 확인 권장).

## 8. Excel 정밀검증 탭 (별도 워크플로우)
"Excel 정밀검증" 탭은 사이드바의 "리뷰 시작"(PDF/XBRL 자동 파이프라인)과 완전히 독립적으로
동작하는 별도 도구입니다(dycmqk02-hub/fin-review-toolkit 프로젝트를 이식). 재무제표 숫자를
Excel에 옮겨 적으면(또는 PDF로 초안을 자동 채운 뒤 직접 검토·수정하면) 그 Excel 내용을
기준으로 검증합니다 - 사이드바에서 PDF/XBRL을 업로드할 필요가 없습니다.

- **① PDF 불러오기(자동 채움)**: 별도/연결 PDF를 선택하면 재무상태표·손익계산서·현금흐름표
  본문을 읽어 Excel 초안을 만들고 저장 위치를 물어봅니다. **자동 추출은 참고용 초안이므로
  저장된 파일을 열어 원문과 대조·수정한 뒤** [③ 검증 실행]을 눌러야 합니다(자본변동표와
  주석은 표 구조가 복잡해 자동 추출하지 않으므로 반드시 직접 입력).
- **② 템플릿 직접 생성**: 빈 템플릿(별도/연결 × BS/IS/CF/SOCE/주석 + 대사규칙 시트)을
  만듭니다. Excel에서 직접 값을 채워 넣는 경우 사용합니다.
- **③ 검증 실행**: 아직 불러온 파일이 없으면 선택창이 뜨고, 이미 불러온 상태면 (①/②로
  방금 만든 파일이든, 이전에 만들어 둔 파일이든) **매번 디스크에서 새로 읽어들여** Excel에서
  방금 수정한 내용을 그대로 반영합니다 - 별도의 "파일 열기"/"다시 불러오기" 버튼이 없습니다.
  검증 후 결과를 4개 탭(합계검증/대사검증/연결-별도 비교/요약)에 표시하고, **회사명과
  기준년월(예: 2612)을 입력해 두었다면** 그 값으로 만든 파일명("회사명기준년월.xlsx")으로
  **다운로드 폴더에 자동 저장**합니다(저장 위치를 묻지 않음). 입력해 두지 않았으면 화면
  표시까지만 하고 저장은 건너뛰며 안내 메시지가 뜹니다.

**4개 결과 탭**(각 탭 상단에도 동일한 설명이 표시됩니다):
- **합계검증**: 각 시트의 '세부'→'소계'→'합계' 산식이 실제로 맞는지 재계산.
- **대사검증**: Excel '대사규칙' 시트에 등록한 규칙대로 대사. **재무제표간 대사**(예:
  현금흐름표 기말현금=재무상태표 현금및현금성자산, 자본변동표 반기순이익=손익계산서
  반기순이익)와 **주석간 대사**(예: 금융상품 범주별 분류표의 기타채권=개별 명세 주석의
  기타채권 합계 - 재무제표 본문과는 무관하게 주석끼리만 비교)를 모두 같은 방식으로
  처리하며, 어느 쪽인지는 등록한 규칙의 시트 조합에 따라 결정됩니다(하나로 고정된 것이
  아님).
- **연결-별도 비교**: 별도/연결에서 이름이 같은 계정과목을 자동 매칭해 금액·차이 나열
  (차이가 있다고 오류는 아닌 검토포인트 후보 목록).
- **요약**: 전체 통계 + 자동화 대상이 아닌 정성적 검토포인트 체크리스트.

**자동 저장되는 파일의 맨 왼쪽 시트 = "차이요약"**: 세 검증(합계검증/대사검증/연결-별도
비교)에서 나온 불일치·차이 항목만 모아 한 표로 보여줍니다. 각 행 오른쪽의 "바로가기" 셀을
클릭하면 원본 Excel 파일(① 또는 ②로 만든 그 파일)의 해당 계정과목이 있는 셀로 바로
이동합니다(외부 파일 하이퍼링크라 원본 파일이 같은 경로에 그대로 있어야 동작하며, 계정과목
이름이 원본과 정확히 일치해야 셀을 찾을 수 있습니다 - 못 찾으면 "-"로 비워둡니다). 파일을
열면 이 시트가 자동으로 맨 처음 보입니다.

원본(fin-review-toolkit)과의 차이: "파일 열기" 버튼은 [③ 검증 실행]에 통합되었고, "검토
결과 내보내기" 버튼은 [③ 검증 실행] 완료 시 자동 저장으로 대체되었으며, 자동 저장 파일
맨 앞에 하이퍼링크가 달린 "차이요약" 시트가 추가되었습니다. 로직(PDF 추출 휴리스틱,
합계검증/대사검증/연결-별도비교 알고리즘)은 `app/rules/excel_review_engine.py`에 동일하게
이식되어 있습니다.

## 9. 커스텀 체크리스트 추가 (내일 반영 예정)
`app/rules/custom_checklist.py`가 이미 확장 포인트로 준비되어 있습니다. CSV 또는 XLSX

|---|---|
| 구분 | 체크리스트 결과 화면 카테고리명 (예: "특수관계자 공시") |

## 10. 감사보고서 리뷰로 확장하는 방법 (추후 작업용 메모)
- `app/audit_engine.py`가 `semiannual_engine.py`와 동일한 인터페이스
  (`run_review(fs_type, accounting_standard, files, settings, pm_consol, pm_separate,
  progress_cb)`, `progress_cb(msg, percent)`)로 스텁이 준비되어 있습니다.
- 확장 시 할 일:
  1. `app/rules/` 아래 감사보고서 전용 체크리스트/의견판단 모듈 추가
     (예: `audit_checklist.py` - 회계감사기준 700/701/705/706 등 기준 문단)
  2. `audit_engine.py`의 `run_review()`를 `semiannual_engine._single_doc_review()`에
     준하는 구조로 구현
  3. `review_engine.py`의 `_ENGINES` 딕셔너리는 이미 `"감사": audit_engine`으로
     연결되어 있으므로 별도 배선 작업 불필요
  4. UI(`app/ui.py`)는 `result.get("not_supported")` 플래그만 보고 있으므로,
     `audit_engine.run_review()`가 `not_supported=False`와 완전한 `sections`를
     반환하면 자동으로 기존 탭 UI에 렌더링됩니다.

## 12. 알려진 제약사항
- 표 합계검산·라벨 교차대사는 PDF 표/텍스트 추출 품질에 좌우되며, 스캔본(이미지 PDF)에는
  적용되지 않습니다(OCR 미포함). 증감분석은 XBRL 제공 시 이 제약을 받지 않습니다(6번 항목).
- 의견유형 판단은 표준 문구("한정의견", "부적정의견", "의견거절" 등) 매칭 기반이므로,
  보고서가 준칙 예시와 다른 표현을 쓴 경우 오판정될 수 있습니다.
- PDF 표 휴리스틱 기반 증감분석표의 당기/전기 컬럼 짝짓기는 위치 기반 추정이며, 표 레이아웃이
  예상과 다르면(특히 자본변동표) 자동 인식에 실패할 수 있습니다 - XBRL을 함께 제공하면
  훨씬 정확합니다(5·6번 항목).
- 연결 vs 별도 비교는 준칙에 명문화된 절차가 아닌 실무 참고용 체크리스트입니다.
- K-GAAP/KIFRS 참조자료 폴더는 최초 1회만 전체 PDF를 인덱싱하며 이후에는 디스크 캐시로
  재사용됩니다. 원본 PDF를 교체/추가하면 자동으로 다시 인덱싱됩니다.
